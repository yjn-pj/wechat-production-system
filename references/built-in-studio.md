# 内置创作台

本 Skill 自带一套可用的写作、配图、封面、截图、验证流程。没有安装其他 Skill 时，必须按本文件执行兜底方案；如果环境中存在增强 Skill，可以调用，但不能因此跳过本文的质量标准。

## 1. 公众号文风引擎

### 声音设定

默认声音是：

> 一个懂工具、肯下场、会讲人话的朋友，把复杂事情拆给普通人听。

写法：

- 第一句给冲突或反差；
- 第二句说明影响；
- 第三句开始给场景；
- 每节结尾回到“怎么做”；
- 允许有个人判断，但不伪造经历；
- 用“我建议”“这里容易错”“别急着”“先跑通”这类口语；
- 对未知、失败、权限和成本保持坦诚。

### 段落节奏

```text
钩子
解释一句
具体场景
操作或证据
错误做法
正确做法
小结
```

段落建议 1-3 行，手机端一屏一个重点。重要判断单独成行。

### 通俗解释模板

第一次出现技术名词时：

```text
它说白了就是……
你可以把它理解成……
它会改变的是……
你需要注意的边界是……
```

禁止只有名词解释，没有场景。

## 2. 图位规划器

生成图片前必须输出图位计划：

```text
图位计划
1. cover-2.35x1
   目的：表达核心冲突
   视觉主体：
   标题留白：
   风格：

2. evidence-<fact>
   目的：证明哪个事实
   来源 URL：
   截取区域：
   图注：

3. diagram-<concept>
   目的：解释什么流程/结构
   输入：
   输出：
   视觉形式：
```

标准模式至少 3 个图位；深度模式至少 4 个图位。

## 3. 图片提示词引擎

每张生成图必须有独立 prompt 文件。Prompt 用一段英文描述，包含：

1. Subject：单一主体；
2. Composition：主体位置和视线动线；
3. Metaphor：解释文章论点；
4. Palette：2-4 个颜色锚点；
5. Lighting：柔光、纸感、印刷光、工作台光；
6. Style：editorial / risograph / hand-drawn / infographic；
7. Negative：no text、no watermark、no neon、no robot；
8. Aspect ratio。

### 低 AI 味 Prompt 模板

```text
Muted editorial illustration in risograph style. A single focal object:
【主体】. It visually explains 【论点】. Use warm off-white paper,
deep navy, brick red, mustard yellow and teal. Soft print texture,
hand-drawn edges, generous negative space, clear area reserved for
Chinese title. No text, no watermark, no neon glow, no robot,
no futuristic particles. 2.35:1.
```

### 生成后处理

- 如果模型文字不稳定，生成无文字底图；
- 使用排版工具添加中文标题和图注；
- 中文标题必须人工检查；
- 保留底图和成品格式。

## 4. 封面设计器

### 封面必须回答

- 这篇文章的冲突是什么？
- 谁该点进来？
- 读者第一眼看到什么？
- 标题放在哪里？
- 小图下还能不能读懂？

### 构图模板

1. 双核心对比：左右两个主体，中间连接线；
2. 工作台场景：工具、资料、人手、结果；
3. 前后对比：旧做法 vs 新做法；
4. 黑板报：手绘板书 + 核心结论；
5. 杂志封面：主体 + 标题留白 + 小标签区。

### 标题排版

- 主标题字号占宽度 60%-80%；
- 副标题不超过主标题一半；
- 留出安全边距 5%-8%；
- 不把重要文字贴边；
- 小图预览必须能读。

### 风格库

优先：

- 编辑部纸感；
- Riso 手绘；
- 黑板报；
- 工作台；
- 低饱和拼贴；
- 信息图。

避免：

- 蓝紫渐变；
- 发光球；
- 赛博城市；
- 机器人；
- 无意义粒子；
- 过度写实人脸。

## 5. 截图工作台

### 可自动截图时

1. 打开原始 URL；
2. 等待页面加载；
3. 截取标题、关键数据或表格；
4. 保留 URL 或页面标题；
5. 命名为 `evidence-<fact>.png`；
6. 在 source ledger 登记来源和时间。

### 无法自动截图时

输出截图任务清单：

```text
请手动截取：
URL：
截取区域：
需要包含：
不需要包含：
建议尺寸：
保存为：
图注：
```

不能让 AI 图替代真实截图。

## 6. 图片验证器

每张图必须检查：

- 是否解释对应论点；
- 是否有正确比例；
- 标题区是否留空；
- 中文是否清晰；
- 是否有乱码；
- 是否有水印；
- 小图是否可读；
- 与整套图风格是否统一；
- 是否误把生成图当证据。

验证输出：

```text
图片验证
✅ cover：主体明确，标题区干净
✅ evidence：官方页面可读，来源可见
⚠️ diagram：文字偏小，建议放大节点
```

不通过就重做，不用“看起来还不错”作为交付理由。

## 7. 外部协作规则

默认使用内置创作台。发现外部 Skill 时，可以把它当作执行适配器，但质量标准、交付结构和终审判断仍必须由本 Skill 控制：

| 可用 Skill | 用来执行 | 本 Skill 兜底 |
|---|---|---|
| khazix-writer | 文风润色 | 内置公众号文风引擎 |
| article-visuals | 图位规划 | 内置图位规划器 |
| peituka-basics | 图片 Prompt | 内置提示词引擎 |
| baoyu-cover-image | 封面生成 | 内置封面设计器 |
| verification | 图片检查 | 内置图片验证器 |
| screenshot / browser | 页面截图 | 内置截图任务清单 |

没有这些 Skill 时，不得拒绝执行；按本文内置方案继续。
